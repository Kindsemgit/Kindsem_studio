# AGENTS.md

Инструкции для любого ассистента (Cursor, Copilot, Claude, ChatGPT и др.).  
Соблюдай их, пока пользователь явно не отменит правило.

## 🔴 Критично — не нарушать

1. **Язык общения** — отвечай на языке пользователя. Язык интерфейса кода и UI — как у пользователя, если не задан иначе.
2. **Секреты** — `.env`, ключи, токены, пароли не читай, не печатай и не коммить. Все правила — в `AGENTS_SECURITY.md`.
3. **Не создавай файлы без просьбы** — не добавляй зависимости и конфиги сверх задачи. Исключения: этот `AGENTS.md`; файлы, которые пользователь назвал; при создании проекта с нуля — каркас из `AGENTS_*.md` нужного стека (корневые `README.md`, `docs/`, `.env.example`, файл манифеста, без лишних пакетов).
4. **Не коммить без просьбы** — commit, push, PR — только если пользователь явно попросил. Не меняй `git config`, не используй `--force`, `--no-verify`, интерактивный rebase.
5. **Не коммить артефакты** — `.venv/`, `node_modules/`, логи, кэши, бинарные дампы, служебные файлы ассистентов.
6. **Опасные действия** — удаление данных, операции с деньгами и реальными аккаунтами, отзыв ключей, публикация в интернет — только после явной просьбы пользователя.
7. **Не обходи репозиторий без нужды** — открывай файлы только под текущую задачу. Не сканируй код «для знакомства». Первым делом читай корневой `README.md` и файл манифеста (`package.json`, `pyproject.toml`, `requirements.txt`). Документация — только `README.md` и папка `docs/` в корне репозитория, не внутри фронтенда и не в `src/`.

## 🟡 Процесс работы

1. **План перед кодом** — если затрагивается более 2 файлов или меняется API / структура / архитектура, кратко напиши план (3–5 пунктов: что тронешь и зачем), и только потом меняй код.
2. **Минимальные изменения** — меняй только то, что нужно для задачи. Без соседнего рефакторинга и «заодно поправить».
3. **Повторяй стиль существующего кода** — имена, структуру, отступы, паттерны уже существующих модулей. Не заводи новый каркас рядом со старым.
4. **Не выдумывай API** — не придумывай эндпоинты, поля, переменные окружения, которых нет в репозитории. Если чего-то не хватает — напиши об этом, не маскируй заглушками.
5. **Остановись вовремя** — не продолжай «улучшать» после выполненной задачи.
6. **Проверка результата** — после изменений запусти проверки из раздела ниже. Если менял UI, проверь как пользователь: открыть, кликнуть, сравнить соседние экраны. Нет браузера — проверь иначе и напиши, что визуально не смотрел.

## 📝 Именование файлов документации

Правило для новых файлов в `docs/`. Старые файлы не переименовывай. Корневые `README.md`, `AGENTS*.md`, `CLAUDE.md` и код под это правило не попадают.

**Формула:** `[дата — опционально]-[тема]-[тип].md`

- Только латиница, строчные буквы, цифры и дефис. Без пробелов, подчёркиваний и кириллицы.
- Дата — в формате `ГГГГ-ММ-ДД`. Ставь её, если документ привязан к моменту (отчёт, разбор ошибки, план на период).
- Тема — о чём документ, 1–3 слова: `auth`, `payments`, `deploy`.
- Тип — что это за документ: `plan`, `report`, `methodology`, `instruction`, `checklist`, `notes`.
- Расширение — `.md`.

**Примеры:**
- `2026-04-21-sales-weekly-report.md`
- `client-onboarding-checklist.md`
- `deploy-instruction.md`
