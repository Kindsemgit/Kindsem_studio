# AGENTS_BACKEND.md

Python-бэкенд. Существующую структуру не ломай. Секреты — `AGENTS_SECURITY.md`.

**Нельзя:** второй каркас, сам выбрать стек, выдумать API/поля/env, новая зависимость, `import *`, голый `except:`, `print`, SQL-склейка, секреты в лог, DROP без просьбы, сервер не на localhost.

## Новый проект

```
src/                 — исходный код
  main.py            — точка входа (без бизнес-логики)
  api/               — роутеры, валидация входа
  core/              — бизнес-логика, сервисы, домен
  db/                — модели БД, репозитории, миграции
  schemas/           — схемы запроса/ответа
  utils/             — логгер, конфиг, хелперы
tests/               — зеркало src/: unit/, integration/, conftest.py
scripts/             — БД, деплой
README.md            — обзор проекта, корень репозитория
docs/                — документация, только .md
.env.example         — имена переменных, без секретов
requirements.txt     — или pyproject.toml, как в проекте
```

Живую раскладку не переименовывай. Не заводи `app/` рядом с `src/`, второй фреймворк, второй `main`.  
Стек (FastAPI / Django / SQLAlchemy / Alembic / Pydantic) — из репозитория или спроси. Папка `schemas/` — место для схем, не повод ставить пакеты. `AGENTS.md` и `README.md` — в корне, не в `src/` и не в `docs/`. Не клади второй `docs/` во фронтенд.

## Код

- 4 пробела, без табов. Строка 88 (или как в проекте). 2 пустые строки между top-level, 1 между методами.
- `snake_case` — модули, функции, переменные; `CamelCase` — классы; `UPPER_SNAKE_CASE` — константы; `_internal` — внутреннее. Не БЭМ.
- Импорты: stdlib → сторонние → свои; группы через пустую строку. Без `from module import *`.
- Типы у аргументов и возврата публичных функций (`typing` или `|` — как в версии проекта).
- Комментарий = *почему*. Docstring — у нетривиального публичного API, формат репозитория.
- Зависимости не добавляй: нет пакета — напиши, не костыль. `async` — как в существующих модулях.

## Слои, API, БД, конфиг

- Слои: `api/` — маршруты и валидация входа. `core/` — логика. `db/` — БД. `main.py` не раздувай. Клиенту не доверяй.
- Схемы — в `schemas/`. Pydantic, pydantic-settings, dotenv — только если уже в проекте, сам не подключай.
- Конфиг — объект из точки входа, не глобальный синглтон.
- Не выдумывай эндпоинты, поля, статусы, env. Нет в репозитории — напиши, не заглушка.
- Новый маршрут — только по задаче. JSON-контракт не переименовывай. Ошибки клиенту — тот же формат, что уже есть.
- Новые таблицы/поля — по задаче. Миграции — если уже есть. DROP/wipe — по явной просьбе.
- SQL только параметризованный. Сессии и транзакции закрывай.
- Настройки из env. В код не вшивай URL, порты, ключи, прод-пути. Локально по умолчанию только `127.0.0.1`.
- `.env.example` — имена новых переменных. `.env` не читай и не печатай. Кэш, логи, данные — не в git; пути из конфига.
- Лови конкретные исключения. Пустой `except` запрещён: лог или проброс.
- Логи — `logging` (или уже принятый). `print` в сдаче не оставляй. Секреты, токены, пароли, ПДн в лог не пиши.
