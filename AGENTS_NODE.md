# AGENTS_NODE.md

Node.js-бэкенд и скрипты. Существующую структуру не ломай. Секреты — `AGENTS_SECURITY.md`.

**Нельзя:** второй каркас, сам выбрать стек, выдумать API/поля/env, новый пакет без просьбы, пустой `catch`, `console.log` в сдаче, SQL-склейка, секреты в лог, DROP без просьбы, сервер не на localhost.

## Новый проект

```
src/                 — исходный код
  index.js           — точка входа (без бизнес-логики)
  routes/            — маршруты, валидация входа
  services/          — бизнес-логика
  db/                — работа с БД, миграции
  utils/             — логгер, конфиг, хелперы
tests/               — тесты, зеркало src/
scripts/             — БД, деплой
README.md            — обзор проекта, корень репозитория
docs/                — документация, только .md
.env.example         — имена переменных, без секретов
package.json         — скрипты start / dev / test
```

Живую раскладку не переименовывай. Не заводи `app/` рядом с `src/`, второй фреймворк, вторую точку входа.  
Фреймворк (Express / Fastify / без него) — из репозитория или спроси. `AGENTS.md` и `README.md` — в корне.

## Код

- Модули — как в проекте; в новом — ES-модули (`"type": "module"`, `import` / `export`).
- 2 пробела, точки с запятой — как в существующем коде.
- `camelCase` — переменные и функции; `PascalCase` — классы; `UPPER_SNAKE_CASE` — константы; `kebab-case` — имена файлов.
- `async` / `await` вместо цепочек `.then()`. Каждый `await` во внешний мир — с обработкой ошибки.
- Комментарий = *почему*. Не комментируй очевидное.
- Пакеты не добавляй: нет пакета — напиши, не костыль. Сначала посмотри, есть ли нужное во встроенных модулях (`node:fs`, `node:path`, `node:test`, `fetch`).

## Слои, API, БД, конфиг

- `routes/` — маршруты и проверка входа. `services/` — логика. `db/` — БД. Точку входа не раздувай. Клиенту не доверяй.
- Не выдумывай эндпоинты, поля, статусы, env. Нет в репозитории — напиши, не заглушка.
- JSON-контракт не переименовывай. Ошибки клиенту — в том же формате, что уже есть.
- SQL только параметризованный. Соединения и транзакции закрывай.
- Настройки из `process.env`, в одном модуле конфига. В код не вшивай URL, порты, ключи. Локально по умолчанию только `127.0.0.1`.
- `.env.example` — имена новых переменных. `.env` не читай и не печатай.
- Лови конкретные ошибки. Пустой `catch` запрещён: лог с контекстом или проброс.
- Логи — принятый в проекте логгер. Секреты, токены, пароли, ПДн в лог не пиши.

## Сдача

- Тесты — как в проекте; в новом — встроенный `node:test` (`node --test`), без установки пакетов. Внешние сервисы и БД подменяй.
- Перед сдачей: успех и типичная ошибка затронутого эндпоинта; относящиеся тесты; ESLint / Prettier — только если уже в проекте (не ставь).
- `npm install <пакет>` — только по просьбе. `package-lock.json` не удаляй.

**Повтор:** не выдумывай API и env, не ставь пакеты сам, параметризуй SQL, не глотай ошибки, не пиши секреты в лог.
